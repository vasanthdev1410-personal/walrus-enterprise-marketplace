2. Major Corrections Applied

M1 – Transactional Outbox alignment
- Replaced legacy outbox_event_id/event_type/event_schema_version semantics.
- Established message_id as the single retry/publication identity.
- Added contract_id, contract_name, message_kind, schema_version, producer_context, conditional target_context, classification and protected payload/reference.
- Added an explicit legacy-to-canonical mapping and C8 lifecycle/index constraints.
- Changed the purpose from Domain Event-only publication to approved Integration Events and Integration Commands.

M2 – C10 persistence-catalogue integration
- Added Privacy Request to Approved Aggregate Roots.
- Added Terms Acceptance Receipt, Privacy Notice Receipt, Consent Record and Identifier Tombstone to Identity-owned records.
- Added Privacy Execution Record to the Privacy Request Aggregate.
- Added Privacy Request aggregate ownership and invariants.
- Added authoritative relationship/constraint entries for all six C10 records.
- Added retention/deletion behavior for all six records.
- Added transaction boundaries for registration evidence, Consent transition, Privacy Request transition, deletion execution and identifier reuse.
- Added approved access patterns and required indexes.

M3 – C10 contracts moved into C8 catalogue
- Removed the loose C10 Privacy Coordination Contracts block.
- Added a Proposed/Gated C10 Privacy Contracts subsection to the authoritative C8 catalogue.
- Defined M01-CMD-004, PRV-CMD-001 and M01-EVT-003 using structured producer, consumer/subscriber, purpose, minimum payload, classification, completion and gating rules.
- Preserved ASYNC_TRANSPORT_TBD and privacy-orchestrator gates.

M4 – Privacy/Deletion state mapping
- Defined Privacy Request State as the orchestration lifecycle.
- Defined Module 01 Deletion Execution State as the DELETION-specific child lifecycle.
- Added an authoritative state-to-safe-projection mapping.
- Defined PARTIALLY_COMPLETED and FAILED_SECURELY behavior without overwriting child state or claiming enterprise completion.
- Clarified M01-ID-002, M01-ID-003 and M01-ID-005 semantics.

M5 – Unique section identifiers
- Added a stable hierarchical identifier to every numbered heading using its owning WEMP Document ID and local section number.
- Added occurrence qualification where an embedded component reused the same local number.
- All 337 hierarchical section identifiers are unique.
- Original visible local section numbers and terminology were retained for traceability.

M6 – Final document control
- Updated the consolidated version to v1.12.
- Replaced the stale v1.1 footer.
- Recorded incorporation of C1–C10 and consolidation findings.
- Preserved Draft and pending-approval status.
