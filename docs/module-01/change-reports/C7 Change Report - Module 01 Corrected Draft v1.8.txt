2. C7 Architecture Applied

- ES256 is the approved Phase 1 JWT signing algorithm.
- Production signing uses a non-exportable AWS KMS asymmetric ECC_NIST_P256 key with ECDSA_SHA_256.
- JWT signing, encryption, lookup/HMAC, CSRF, audit-integrity and provider secrets have separated purposes and access policies.
- Signing keys use GENERATED, ACTIVE_SIGNING, VERIFY_ONLY, RETIRED, DESTROYED and COMPROMISED lifecycle states.
- Normal rotation, verification overlap and emergency compromise response are deterministic.
- M01-KEY-001 defines the public JWKS contract and is represented in the endpoint, DTO, rate-limit and degraded-mode catalogues.
- Reversible secrets use authenticated envelope encryption with a non-exportable KMS KEK.
- Passwords use Argon2id with versioned, Security-approved parameters and progressive rehash.
- PostgreSQL remains authoritative; Redis remains a non-authoritative projection/cache.
- All unresolved numerical security and operational values remain explicit TBDs and block affected production approval.
