2. C5 Architecture Applied

- 39 Phase 1 REST operations are catalogued with unique contract IDs.
- Nine endpoint exposure classes are defined.
- Every operation has exactly one exposure class and operation-specific security, idempotency, version, rate, response, error and audit metadata.
- Operation-specific request and response DTO catalogues are authoritative and independent of C4 persistence.
- Web uses in-memory Bearer Access Tokens and a Secure HttpOnly SameSite=Strict Refresh Token cookie with CSRF protection.
- Flutter uses operating-system-backed secure storage for Refresh Tokens and Bearer Access Tokens.
- State-aware C2 Session validation remains mandatory.
- Idempotency-Key and ETag/If-Match contracts are defined.
- Stable Module 01 errors and named rate-limit classes are defined.
- The reviewed/versioned OpenAPI contract is authoritative and CI-enforced.
