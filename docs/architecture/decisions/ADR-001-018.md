# Accepted architecture decisions

## Context

WALRUS requires a production-oriented foundation that supports concurrent web, API, mobile,
platform, security, and QA work without implementing business functionality.

## Decisions

- Use one Git monorepo rooted at the current workspace, orchestrated by Turborepo and pnpm.
- Use Next.js App Router, NestJS, PostgreSQL, Redis, Cloudflare R2, AWS, and Flutter.
- Use Prisma for forward-only database migrations; production correction uses a new migration.
- Provide a host-development Docker profile and a full-container integration profile.
- Target AWS ECS Fargate and Terraform in Phase 1 without provisioning live resources in Module 00.
- Keep customer, seller, admin, and super-admin route groups isolated within one Next.js app.
- Keep customer and seller mobile features isolated in one Flutter app; exclude mobile admin.
- Structure future NestJS modules as presentation, application, domain, and infrastructure layers.
- Run Prometheus and Grafana locally; keep Sentry and CloudWatch integration-ready and optional.

## Consequences

The platform has one versioned workspace and shared quality gates. Portal and role boundaries must
remain enforceable so deployables can be extracted later. Cloud deployment requires a future,
approved environment configuration before Terraform can create resources.

## Approval

Status: Accepted. Authority: Product/architecture owner through the approved Module 00 specification
and recorded implementation decisions. Date: 2026-08-03.
